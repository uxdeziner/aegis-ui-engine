UX engineering case study

The design system your AI agents actually follow.

AI coding agents produce UI quickly, and without guidance it all looks the same: off-brand gradients, inaccessible contrast and a new border radius on every card. AegisUI is a token-and-rules layer (design tokens, a CLAUDE.md rulebook, component contracts and CI guardrails) that turns agent output into production UI the first time.

The brief

The problem isn't that AI writes UI. It's that AI writes generic UI.

Every prompt starts from zero brand context, so every screen gets reviewed, rejected and regenerated. AegisUI moves the design system into a form the agent reads.

01 / Challenge

Speed without standards

  • Agents invent colors, spacing and radii on every run
  • Accessibility is accidental, not guaranteed
  • Design review becomes a manual rework queue
  • Token spend grows with each regeneration loop
02 / Approach

Make the system machine-readable

  • Single source of truth in DTCG tokens.json
  • Compiled to CSS variables + typed exports
  • CLAUDE.md rules + per-component contracts
  • Token lint, axe and visual checks in CI
03 / Outcome

First-pass output that ships

  • Generated UI uses only approved tokens
  • Contrast and focus states enforced by contract
  • Fewer regeneration loops, so fewer tokens
  • Designers review intent, not hex codes

What the agent got wrong without AegisUI

  • Status shown by color alone, which color-blind users can't read
  • Placeholder used as the only label on search
  • Four number formats in one column, all left-unaligned
  • Clickable <span> with no keyboard access
  • Hard-coded colors that ignore dark mode (switch theme to see it)
  • Vague CTA ("Click Here!") and an alert with no specifics
